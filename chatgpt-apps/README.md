# Five ChatGPT apps, one server

Five ChatGPT apps (Apps SDK / MCP Apps — what the directory now calls *plugins*), each built around a job people already do by hand every week, where ChatGPT alone is unreliable, and where no entrenched brand owns the slot in the app directory. One stateless Node process serves all five; each app has its own MCP endpoint so it is a separate listing in ChatGPT.

| App | Endpoint | Tools | The gap it fills |
| --- | --- | --- | --- |
| **Verified Citations** | `/citations/mcp` | `format_citation`, `lookup_reference`, `verify_references`, `export_bibliography` | Scribbr / Citation Machine get 10M+ visits a month; studies find ChatGPT fabricates 18–38 % of references. Every lookup resolves to a real DOI via Crossref/OpenAlex. No citation app in the directory. |
| **Calendar Invite & Date Math** | `/calendar/mcp` | `create_calendar_invite`, `calculate_date`, `convert_time_zones`, `find_meeting_times` | Turns a plan into a real .ics + Google/Outlook links with no OAuth; exact business-day and time-zone math where LLMs are documented to slip. |
| **Timesheet & Overtime Calculator** | `/timesheet/mcp` | `calculate_timesheet`, `add_hours` | Hourly workers and small businesses total hours weekly; breaks, overnight shifts, rounding, 40 h / 8-12 h overtime rules, printable PDF. No competitor found. |
| **Mortgage & Loan Calculator** | `/loan/mcp` | `calculate_mortgage_payment`, `calculate_loan_payment`, `calculate_home_affordability`, `compare_refinance` | "mortgage calculator" alone is ~3.4 M searches/month; 360-row amortization is error-prone in prose. Interactive breakdown + chart + CSV schedule. |
| **QR Code Studio** | `/qr/mcp` | `create_qr_code`, `create_wifi_qr_code`, `create_vcard_qr_code` | 7 M visits/month to the market leader; image models draw QR codes that don't scan. Real encoder, PNG/SVG downloads, Wi-Fi and vCard presets. One competitor (QRCM). |

Screenshots of every widget (light and dark) are in [`screenshots/`](screenshots/) — generated by `npm run preview`, which renders each widget in headless Chromium inside a simulated MCP Apps host.

## How it's built

```
src/
  kit/            shared runtime
    http.ts       Express: /<slug>/mcp (stateless Streamable HTTP), /<slug>/files/:token, /healthz, /privacy
    meta.ts       tool/widget metadata emitting BOTH MCP Apps keys (_meta.ui.*) and ChatGPT aliases (openai/*)
    files.ts      stateless signed download links (HMAC + deflated payload, 7-day expiry)
    bridge.js     widget runtime: ui/initialize handshake, tool-result/host-context events, window.openai fallback
    base.css      widget styles using the host's CSS variables with fallbacks (light + dark)
  apps/<slug>/
    lib.ts        pure logic (unit-tested)
    server.ts     defineApp(): tools, schemas, annotations, descriptions, sample calls
    widget.html   the inline UI
    chatgpt-app-submission.json   upload this in the submission form
  smoke.ts        MCP-client end-to-end test
  preview.ts      Playwright widget render check + screenshots
  submission.ts   checks each submission JSON against the live tool list
```

Design decisions that matter for review and discovery:

- **Standard first, aliases second.** Tools link to widgets with `_meta.ui.resourceUri` (MCP Apps spec 2026-01-26, which ChatGPT now hosts) and mirror `openai/outputTemplate`, `openai/toolInvocation/*`, `openai/widgetDescription`, `openai/widgetCSP` so older ChatGPT builds and inspectors behave identically. Widget MIME type is `text/html;profile=mcp-app`.
- **Every tool declares all three hints explicitly** (`readOnlyHint`, `destructiveHint`, `openWorldHint`) plus `idempotentHint` and an `outputSchema`. Missing hints are the #1 rejection reason. Only the two Crossref tools are `openWorldHint: true`.
- **Descriptions start with "Use this when…"** followed by the literal phrases people type, then a "Not for…" clause pointing at the sibling tool. This is the main ranking input you control.
- **Zero external domains in widgets.** CSP is empty; charts are inline SVG; fonts come from the host. Nothing to flag.
- **Stateless downloads.** ChatGPT's `downloadFile` bridge method isn't live and sandboxed iframes can't trigger downloads, so every file (.ics, .pdf, .csv, .png, .svg, .bib, .ris) is a signed URL the widget opens with `ui/open-link`. The server rebuilds the file from the token — no storage, scales horizontally.
- **No file uploads as input.** `openai/fileParams` arrives missing on ~10 % of calls per OpenAI's issue tracker, which is why there's no "PDF to Excel" app here.
- **structuredContent matches outputSchema exactly.** Clients validate with `additionalProperties: false`; the smoke test catches drift.

## Run it

```bash
cd chatgpt-apps
npm install
npm run check        # typecheck + unit tests + MCP smoke test + submission validation
npm run preview      # renders every widget in Chromium → screenshots/
npm run dev          # http://localhost:8787  (APPS=qr,loan to serve a subset)
```

`npm run smoke` is the important one: it connects with the real MCP client over Streamable HTTP, lists tools and resources, asserts the metadata contract, calls every sample, and downloads every file link.

### Test inside ChatGPT (developer mode)

1. `npm run dev`, then expose it: `ngrok http 8787` (or `cloudflared tunnel --url http://localhost:8787`).
2. Set `PUBLIC_BASE_URL=https://<your-tunnel>` in `.env` (download links are built from it) and restart.
3. ChatGPT → **Settings → Apps & Connectors → Advanced settings → Developer mode**.
4. **Create** a new app per endpoint, e.g. `https://<your-tunnel>/citations/mcp`. No auth.
5. In a chat, try the golden prompts below. After changing any tool description, **refresh** the app in settings so ChatGPT reloads the descriptors.

## Deploy

Any host that runs a container with HTTPS works. The repo ships `Dockerfile`, `render.yaml` (Render blueprint) and `fly.toml`.

```bash
# Fly.io
fly launch --no-deploy
fly secrets set FILES_SECRET=$(openssl rand -hex 32) PUBLIC_BASE_URL=https://chatgpt-apps.fly.dev CONTACT_EMAIL=you@example.com
fly deploy
```

Environment: `PUBLIC_BASE_URL` (required in prod), `FILES_SECRET` (required in prod; links break on restart without it), `CONTACT_EMAIL` (optional; gets you Crossref's faster "polite pool"), `APPS` (optional subset), `PORT`.

The process prints one JSON line per tool call (`{"event":"tool_call","app":"loan","tool":"calculate_mortgage_payment","ms":12,"outcome":"ok"}`). Count those per app per day — that's the traction signal for step 5 of the plan.

## Submit (per app)

Each app is its own submission. The form fields are pre-filled from `src/apps/<slug>/chatgpt-app-submission.json` (OpenAI's import schema: app info, hint justifications, exactly 5 positive + 3 negative test cases). `npm run submission` proves the JSON matches the server.

Checklist pulled from OpenAI's submission skill and the public rejection post-mortems:

- [ ] Organization verified in the OpenAI platform dashboard by an **Owner**; the developer name you enter must match the verified name exactly.
- [ ] Production HTTPS endpoint (not a tunnel). Reviewers try to connect; a 5xx or redirect is an automatic reject.
- [ ] `PRIVACY.md` edited (operator name, contact) — it's served at `https://<host>/privacy`; paste that URL.
- [ ] Support contact email.
- [ ] Logo + screenshots using OpenAI's Figma screenshot template (screenshots taken outside the template get rejected). Use `screenshots/*.png` as the source frames.
- [ ] Demo video showing the app on desktop, iOS and Android.
- [ ] Run the five positive test prompts in developer mode and confirm the expected outputs in the JSON before submitting — "test cases did not produce correct results" is the second most common rejection.
- [ ] Category per JSON (PRODUCTIVITY / BUSINESS / FINANCE / EDUCATION). Subtitles are ≤ 30 characters (validated).
- [ ] Nothing here sells anything, shows ads, or asks for sensitive data (no SSNs, card numbers, credentials — the Wi-Fi password is the one credential-like input, and it's the product).

## Golden prompts

Use these to tune metadata: run each, note whether the right tool fired, change one description at a time. Aim for high precision on the negatives first (an app that over-triggers gets down-ranked).

**Direct** (names the job): "make a QR code for my wifi", "add this to my calendar", "calculate my overtime this week", "mortgage payment on a $450k house", "cite this in APA".

**Indirect** (describes the outcome): "guests keep asking for the wifi password — anything easier?", "I need this dentist appointment on my phone", "did I go over 40 hours?", "what would $380k at 6.5% cost me a month?", "are the references in my essay real?".

**Negative** (must not trigger): "what does this QR code say?" (decode), "what meetings do I have tomorrow?" (reads calendar), "how much tax is withheld?" (payroll), "what are rates today?" (market data), "summarize this paper" (not a citation task). The three negatives per app in the submission JSON are the canonical set.

## Known limits & next steps

- **Crossref/OpenAlex could not be reached from the build sandbox**, so the citations lookup path is unit-tested with a recorded Crossref response and its "service unavailable" path, but not against the live API. First thing after deploy: `verify_references` with the LeCun 2015 Nature reference should come back **verified** with DOI `10.1038/nature14539`.
- Citation styles implement the mainstream cases (journal article, book, chapter, website, report, thesis, conference paper). APA sentence-case for titles is left as typed; the widget tells the user.
- Widget state (`setWidgetState`) isn't used — every widget is a pure render of the last tool result, so there's nothing to persist.
- Signed download tokens live in the URL (deflated JSON). A 60-row timesheet is ~1.5 KB; a 200-reference bibliography is ~8 KB, which some proxies cap. If that bites, swap `files.ts` for a 7-day object-store write — the interface stays the same.
- The ranking signals ChatGPT uses in-conversation aren't public beyond "name, descriptions, usage". Expect to iterate descriptions weekly against the tool-call log.
